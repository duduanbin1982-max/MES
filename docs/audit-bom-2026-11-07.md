# BOM 管理模块审计报告

> 审计对象：`/bom`（项目装备 BOM：结构树 / 0-3 级清单 / 成本 / 健康度 / CSV 导入 / ECO 对比 / 风险项）  
> 审计日期：2026-11-07  
> 审计方式：代码走读（`services/bom/**` 25 个文件、`frontend/src/views/bom/**`）+ 生产接口实测 + 数据完整性 SQL 检查  
> 生产数据：BOM 83 行 / 5 个项目装备；工序节点引用 BOM 167 处

**整改前评级：C+** —— BOM 树、成本、健康度、CSV 导入、ECO 对比功能都在，但存在 **2 个 P1（权限错配、删除破坏工艺树）+ 4 个 P2（成本低估、500 错误、导入非原子、无审计）+ 1 项数据问题（实例1 双根）**。

**整改后：A-（2 个 P1 + 4 个 P2 + 数据修复已全部完成）**

| 编号 | 级别 | 问题（实测） | 状态 |
|---|---|---|---|

## 1. 模块现状

```
BOM 管理 /bom
├─ 结构树 / 0-3 级清单：GET /equipment_instances/:id/bom、/levels
├─ 新增/更新/移动/删除：POST /equipment_instances/:id/bom、PUT /bom/:id、POST /bom/:id/move、DELETE /bom/:id
├─ CSV 导入：POST /equipment_instances/:id/bom/import、GET .../import-template
├─ 最低三级骨架：POST .../bom/init-minimum
├─ 成本/健康度/校验/业务视图：GET .../bom/cost、/health、/validate、/business-views
├─ ECO 对比：GET .../bom/compare
└─ 风险项：GET .../bom/risk-owner-options、POST .../risk-items/*
```

数据模型：`instance_bom` 单表树（parent_id + tier + level_code + sort_order），含版本/ECO/生效期、替代料、虚项、关键件、易损件、单价/重量等；BOM 节点被工艺树（`process_nodes.bom_node_id`）引用。

## 2. 发现与整改明细

### B-1（P1）权限错配：BOM 责任人写不了 BOM

实测：`engineer01` 新增 BOM 节点 → **403「权限不足, 需要: equipment:write」**；BOM 路由规则只挂 `equipment:*`。

整改：
- 新增 BOM 专项权限规则（位于通用规则之前）：
  - 读：`equipment:read OR process:read OR material:read`；
  - 写：`equipment:write OR process:write OR material:write`；
  - 覆盖 `/equipment_instances/:id/bom/**` 与 `/bom/:id`、`/bom/:id/move`；
- 前端 `canEdit`（同上任一写权限）：新增根节点/子部件、生成骨架、CSV 导入、节点编辑/删除按钮按权限显示；`LevelTable` 增加 `editable` 属性。

实测：engineer 新增 BOM → **200**（权限生效）。

### B-2（P1）删除 BOM 节点破坏工艺树

`deleteBomNodeCascade` 只按子树级联删除，不检查 `process_nodes.bom_node_id` 引用（生产 167 处）→ 删除后工艺树节点指向不存在的 BOM 节点。

整改：
- 删除前统计引用；有引用默认返回 **409**（附带 `process_node_ids` 前 20 个）；
- `?force=1` 时先 `UPDATE process_nodes SET bom_node_id=NULL` 再级联删除，返回 `cleared_process_nodes`；
- 写审计 `bom.delete`（含级联数量/解除引用数量）；
- 前端删除遇到 409 弹出二次确认，确认后自动带 `force=1` 重试。

实测：删除被 1 个工序引用的节点 → **409**；force 删除 → 200（`cleared_process_nodes:1`，引用置空）。

### B-3（P2）成本汇总漏乘父数量

`calcCost` 叶子节点成本含自身数量，但非叶子节点的子树成本直接相加，**未按父 `quantity` 放大**；多件装配（如 2 套组件）成本被低估。

整改：非叶节点 `cost = 子树单位成本 × 父数量 + 自身成本`（自身成本 = 单价 × 数量 × 损耗）；幽灵件自身成本为 0。

单测：2 套装配 ×（3 件 × 10 元）= 60；根节点 + 1 件 × 5 元 = 65。

### B-4（P2）无效数据/500

- 不存在实例插入 BOM 原返回 500（`recomputeStructureMetadata` 路径异常）→ 增加实例存在校验，返回 **404「项目装备不存在」**；
- `validateNode` 新增：`unit_price >= 0`、`weight >= 0`、`alternative_priority >= 1` 整数。

实测：负单价/负重量更新 → **400**，错误逐项列出。

### B-5（P2）CSV 导入非原子

原实现逐行插入、失败行跳过 → 部分成功留下"半套 BOM"。

整改：默认原子导入——任一行校验失败则**整批回滚**并返回 400（含 `total/error_list`）；`allow_partial:true` 保留逐行导入；前端导入失败时显示首行错误原因。
实测：2 行 CSV（1 行非法）→ **400「已全部回滚」**，行数不变；`allow_partial` → 200 且 inserted=1。

### B-6（P2）BOM 无审计

实测：BOM 操作前后 `audit_logs` 0/0（整改前）。
整改：新增 `bom.init_minimum / bom.create / bom.update / bom.move / bom.delete / bom.import` 审计（操作人、资源 ID、前后值摘要）。
实测：插入后审计 +1，最近动作 `bom.create`。

### B-7（P2）数据完整性：实例 1 双根

SQL 检查：实例 1 有 2 个 `parent_id IS NULL` 的 0 级根（id1 legacy 空字段根 + id68 外购成品 qty3），违反"每实例单根"约束；另有 1 项需修复。

整改：`scripts/migrate-bom-integrity.js --apply`：
- 保留最小 id 根节点，多余根节点挂到保留根下（成为 1 级部件）；
- 悬空/跨实例 `parent_id` 重挂到本实例根；
- 重算 `tier/level_code/sort_order`。
实测：实例 1 根节点 **2 → 1**；`/bom/validate` 仍会提示字段缺失（历史数据质量问题，见边界）。

### B-8（P3，记录）

1. `version/eco_id/effective_*` 只是字段，没有版本树/ECO 流程/生效期校验（compare 仅按 `version` 精确匹配）；
2. 替代料组只校验"替代料必须填组"，未校验同组物料、同父节点、优先级唯一；
3. 成本仅"单价 × 数量 × 损耗"，不含工时/制造费用；
4. CSV 导入不自动创建缺失物料，按 `material_code` 匹配不到会跳过（需先建主数据）；
5. ECO 对比以 `parent_id+物料+图号` 为键，结构移动会显示为新增/删除（语义偏差）。

## 5. 复验方式

```bash
node --test tests/bomGovernance.test.js
node scripts/migrate-bom-integrity.js --apply   # 幂等
```

前端：`/bom` → Ctrl+Shift+R：
1. 用 engineer01 登录：新增/编辑/导入按钮应可用（整改前 403）；
2. 用 reader 角色（无 equipment/process/material write）登录：新增/删除按钮隐藏；
3. 删除一个被工艺树引用的 BOM 节点 → 提示"被工序节点引用"，二次确认后强制删除；
4. CSV 导入包含一条错误行 → 提示"已全部回滚"，BOM 不变化；勾选/接口传 `allow_partial` 才逐行导入。
