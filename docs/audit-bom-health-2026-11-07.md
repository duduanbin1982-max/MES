| 能力 | 交付 |
|---|---|
| BOM 健康分 | 0~100 分 + A/B/C/D 等级 + 结构化问题清单 + 根节点状态 + 发布门槛判断 |

## 1. BOM 健康分

`GET /api/equipment_instances/:id/bom/health` 在原健康度基础上增加：

- `grade`（A≥90 / B≥75 / C≥60 / D<60）；
- `root_state`（single/missing/multiple/empty）与 `root_count`；
- `issues`：结构化问题（severity/code/message/count/fixable），覆盖结构错误、警告、重复物料/图号、缺物料/图号、缺材质/表面处理、缺单价、缺版本、缺工艺路线、替代组、无图纸等；
- `release_gate`：`min_score`、`score`、`can_release`、`blockers`。

评分仍按问题扣分（结构错误 8 分/项、重复 5/4 分、缺物料/图号 4 分、材质/表面 3 分、品牌/单价/替代 2 分、工艺/图纸 1 分），最低 0 分。

## 2. 发布门禁

发布版本 `POST /api/equipment_instances/:id/bom/versions/release`：

1. 先做结构校验（原有 `validateTree`，errors 不为 0 直接拒绝）；
2. 再计算健康分；低于门槛时返回 400，`details` 包含：
   - `score / min_score / grade`
   - `blockers`（结构错误摘要 + “健康分低于门槛”）
   - `issues`（前 20 条 error/warning）
3. 允许管理员强制发布：`force: true` 且当前用户 role=admin 或权限含 `*`；强制发布会在版本 notes 中记录“强制发布（健康分 X）”，并返回 `forced: true`、`health_score`、`health_grade`；
4. 门槛可通过环境变量 `BOM_RELEASE_MIN_SCORE` 调整（默认 70）。

前端发布失败时展示前 4 条阻断原因，而不是仅显示“发布失败”。

## 3. 缺根修复向导

API：
- `GET /api/equipment_instances/:id/bom/repair/preview`
- `POST /api/equipment_instances/:id/bom/repair/apply`

诊断输出：
- BOM 行数、0 级根节点数/列表、无父节点数、孤儿数、跨实例父节点数、可自动修复数、需人工数；
- 修复动作（带数量）：
  - `create_root`：无 0 级根节点时创建 0 级整机节点（空 BOM 也可创建，但仍需补 1/2 级）；
  - `attach_parentless`：把 tier=1 的无父节点/孤儿挂到根节点；
  - `merge_roots`：多根时指定主根，其余 0 级根降为 1 级并整棵子树 tier+1；
  - `manual`：tier≥2 的孤儿/无父节点，出于结构安全只做提示，不自动挂接；
- 预览同时返回当前健康分/校验结果。

执行：
- 事务内执行所选动作，写 `bom.repair_apply` 审计（修复前后根数、孤儿数、健康分、创建/挂接/合并数量）；
- 返回修复后的健康分/校验，便于前端立即刷新；
- 幂等：重复执行时已无对应问题，自动不再产生动作。

前端：
- BOM 结构树工具栏新增“缺根修复”按钮；
- 弹窗展示诊断、动作勾选（多根时选择保留根）、健康问题前 12 条；
- 执行成功后刷新 BOM 与健康分。

## 6. 已知边界

1. 健康分模型为启发式扣分，后续可按 TBM 项目类型配置权重/门槛；
2. 缺根修复只自动处理 **tier=1** 的无父/孤儿节点；tier≥2 需人工确认，避免层级错乱；
3. 多根合并会整体下移非主根子树层级（tier+1），执行前需确认结构语义；
4. 空 BOM 只能创建根，仍需补 1/2 级；建议修复后继续用“生成最低三级骨架”/导入；
5. 强制发布仅管理员；建议增加“强制发布原因”必填与审批流；
6. 当前无健康分历史趋势；后续可记录每日健康分用于治理考核。
