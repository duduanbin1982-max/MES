# 工单管理（/work-orders）

> 页面：`项目与装备 → 工单管理`（`/work-orders`）  
> 代码：`frontend/src/views/WorkOrders.vue`、`services/workOrderService.js`、`app/workflow/workOrderDefinition.js`  
> 2026-11-05 审计整改（详见 `docs/audit-work-orders-2026-11-05.md`）。

## 1. 状态与流转

6 个状态（唯一来源 `app/workflow/workOrderDefinition.js`）：

| 状态 | 中文 | 说明 |
|---|---|---|
| `pending` | 待派工 | 新建默认 |
| `dispatched` | 已派工 | 派工后 |
| `in_progress` | 进行中 | 开工后 |
| `paused` | 已暂停 | |
| `completed` | 已完成 | 完工或累计报工达到计划数量时自动完成 |
| `cancelled` | 已取消 | 取消后不可恢复 |

事件：`dispatch` / `start` / `pause` / `complete` / `report` / `cancel`。状态机负责校验合法流转，错误文案已中文化。

## 2. 页面能力

| 区域 | 内容 |
|---|---|
| 工单列表 | 项目/状态筛选 + 快捷筛选（全部/待派工/已派工/进行中/已完成）；**计划开始/结束 + 实际开始/结束 + 实际工时**；状态中文标签 |
| 操作 | 详情（计划/实际/派工/数量 + 操作流水）、齐套检查、流转时间线、取消（有权限且未完成时） |
| 新建工单 | 项目、工单号、标题、预估工时、计划起止、优先级（紧急/高/普通） |
| 补齐计划日期 | 只有一端缺失的工单按预估工时自动补齐（有结束回推开始、有开始推算结束）；两端全空的留人工排 |
| 待派工 tab | 待派工且未派人的工单；派工弹窗（人员/工位/计划起止） |

## 3. 权限

| 动作 | 角色 |
|---|---|
| 查看列表/详情 | `work_order:read`（受行级数据范围约束） |
| 创建 / 派工 / 改工位 / 取消 | `work_order:write` + 车间主任 / **计划员** / 管理员 |
| 状态流转（transit） | 车间主任 / 管理员 |
| 报工 / 操作流水 | 车间主任 / 计划员 / 焊工 / 工人 |
| 焊接记录 | 焊工 / 工人 / 管理员 |

> 2026-11-05 起计划员可创建/派工/取消（原守卫只放行主任/管理员，计划员在页面看到入口但保存必失败）。

## 4. 派工规则（2026-11-05 新增校验）

1. 工单状态必须是 `pending` 或 `dispatched`；
2. 人员必须存在且在职；工位必须存在且启用；
3. 同一人员已有其它 active 工单 → 提示重复派工，`force=true` 可强行并行派工；
4. 校验全部通过后才在事务里写工单 + 资源占用，避免"校验失败但计划时间已改"。

## 5. 报工规则

- 工时/完成数量/缺陷数量不能为负；
- 累计完成数量达到 `quantity_planned` 时自动完工并写 `actual_end`；
- 响应返回 `over_reported`（累计超过计划时为 true）与累计数量，现场可据此提示超报。

## 6. 计划日期治理

- 创建工单时即可填计划开始/结束，结束不能早于开始；
- 历史工单若只有一端计划时间，可用「补齐计划日期」按 `estimated_hours` 推算另一端；两端都空的保留人工排期（列表提示「另有 N 张完全未排期」）；
- 接口：`POST /api/work_orders/backfill-dates[?dryRun=1]`。


## 8. 工单 ↔ 工序关联（1:1，2026-11-05 新增）

确认规则：**一张工单对应一个工序**。

| 项 | 说明 |
|---|---|
| 数据 | `work_orders.process_node_id`（指向 `process_nodes.id`，空表示未关联） |
| 唯一性 | 唯一部分索引：同一工序只能被一张「未取消」工单占用；工单取消后释放，可重新关联 |
| 校验 | 工序必须存在且与工单同项目；已被其它未取消工单占用时拒绝 |
| 创建 | 新建工单弹窗可选「关联工序」（下拉按项目过滤，默认只列未关联的工序） |
| 列表/详情 | 列表新增「关联工序」列；详情抽屉显示工序及其当前状态，可直接改绑/解除 |
| 接口 | `GET /api/work_orders/process-node-options?equipment_instance_id=&only_unlinked=1`、`PUT /api/work_orders/:id/process-node` |
| 自动回填 | `POST /api/work_orders/backfill-process-nodes[?dryRun=1]`：按「同项目 + 同子系统 + 标题包含工序名」保守匹配，多候选取标题中最先出现者，匹配不到跳过并提示人工选择 |
| 存量迁移 | 已有库执行 `node scripts/migrate-wo-process-node.js --apply`（幂等，支持 `--db` 指定库；`--verify` 只校验） |

**生产现状**：WO-TBM2026001-S3-001「前盾下料+卷制+焊接」已自动关联 #135 下料；其余 3 张（推进油缸组对 / 刀盘体下料 / TEST-001）在同项目同子系统中没有同名工序，保留「未关联」，可在详情里手工选。

**注意**：关联目前只做**归属**（知道这张工单对应哪道工序），不会自动把工单状态/工时回写工序（跨域写需走额外授权；工序状态仍由排程/报工链路驱动）。

## 9. 已知边界

1. 列表未分页（单项目几十张内可接受），优先级只显示 1/2/3；
2. 无工单附件/描述编辑、无批量创建、无删除（取消代替）；
3. 工单 ↔ 工序只做归属，不做状态/工时双向同步（如需回写需新增跨域写授权与同步规则）。
