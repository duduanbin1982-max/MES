## 2. P0：现场可用

### 2.1 扫码离线队列

新增：

```text
frontend/src/mobile/scanQueue.ts
frontend/src/mobile/useScanSync.ts
```

机制：

- 扫码 start/pause/complete 先尝试在线提交；
- 离线或网络异常时写入 IndexedDB `tbm_mobile.scan_queue`；
- 记录动作、工单码、数量、备注、发生时间、操作人、重试次数；
- 联网后按 `createdAt` 顺序补传；
- 失败分两类：
  - 网络/5xx：保留 pending，继续重试；
  - 4xx：标记 failed，需人工“重试失败”；
- 队列绑定当前登录用户，换用户不会代传；
- 页面显示“待同步 N 条 / 失败 N 条”。

### 2.2 服务端幂等

迁移 `034_scan_idempotency.sql`：

```text
scan_action_receipts
  idempotency_key PRIMARY KEY
  device_id
  action / target_type / target_id / operator_id
  response_json
  created_at
```

- 客户端每次动作生成 `Idempotency-Key`；
- 服务端如果已存在回执，直接返回原结果；
- 重复补传不会重复写操作、不会重复启动/暂停/完成计时；
- 回执记录设备 ID，便于审计。

### 2.3 离线发生时间

离线补传如果使用服务器接收时间，计时会从“补传时刻”开始，导致工时错误。

本次增加：

```text
occurred_at
```

- 扫码时客户端记录 `occurred_at`；
- 服务端校验时间格式和“不超过未来 5 分钟”；
- 操作流水、actual_start/actual_end 使用 occurred_at；
- 计时按真实发生时间汇总。

### 2.4 摄像头扫码

`/scan` 新增“摄像头扫码”：

```text
BarcodeDetector + getUserMedia
```

- 手机浏览器优先调用后置摄像头；
- 支持 QR / Code128 / EAN13 / Code39；
- 识别后自动填入并查询工单；
- PDA 扫码枪继续走键盘输入；
- 不支持的浏览器显示提示，不影响扫码枪/手输。

### 2.5 屏幕常亮

计时状态为 `running` 时请求：

```text
navigator.wakeLock.request('screen')
```

- 暂停/完成/离开页面释放；
- 页面重新可见时自动重新申请；
- 计时面板显示“屏幕常亮已开启”。

## 3. P1：移动体验

### 3.1 PWA

新增：

```text
frontend/public/manifest.webmanifest
frontend/public/sw.js
frontend/public/icons/icon-192.png
frontend/public/icons/icon-512.png
```

能力：

- 可添加到主屏幕（standalone）；
- 应用壳缓存；
- 静态资源 stale-while-revalidate；

- 导航请求离线回退 `index.html`。

`/mobile-center` 提供“安装到主屏幕”入口。

### 3.2 工单移动卡片

`/work-orders` 在 ≤768px：

- 隐藏桌面表格；
- 显示工单卡片：
  - 工单号、项目、标题、状态；
  - 现场用时、计时状态；
  - 完成数量/计划数量；
  - 开始 / 暂停 / 完成 / 详情按钮。

移动卡片动作同样支持离线暂存。

### 3.3 同步状态

- 顶部 Header 显示“待同步 N”/“同步失败 N”；
- `/scan` 显示同步提示和“立即同步 / 重试失败”；
- `/mobile-center` 显示队列数量与操作入口。

## 4. P2：设备与管理

```text

  device_id + user_id UNIQUE
```

API：


## 6. 当前边界与风险

1. **摄像头扫码依赖 BarcodeDetector**：Android Chrome 可用；iOS Safari 不支持时提示使用扫码枪/手输。
2. **Wake Lock 浏览器支持有限**：部分 iOS/旧版浏览器不支持，不报错但不生效。
3. **离线队列只覆盖扫码动作**：异常上报、备注、报工审批未离线化。
4. **occurred_at 信任客户端时间**：服务端只限制未来 5 分钟，未限制过旧时间；建议后续加设备时间校验/审计。
5. **幂等回执在动作成功后写入**：极端“动作成功但回执写入前崩溃”仍可能重复，需后续在同一事务内落回执。
6. **PWA 缓存最近工单**：登出已清数据缓存；共享 PDA 仍建议下班清理站点数据。
7. **服务端推送/生物识别未完成**，需要基础设施和额外接口。

## 7. 复验步骤

1. 手机/PDA 打开 `/scan`；
2. 断网扫工单 → 开始 → 页面显示“待同步 1 条”；
3. 恢复网络 → 自动补传 → 工单进入 in_progress，计时从离线发生时间起算；
4. 重复补传同一条 → 不重复写操作；
5. `/work-orders` 手机端显示卡片，可直接开始/暂停/完成；
6. 计时中页面显示“屏幕常亮已开启”（支持浏览器）；
7. `/mobile-center` 绑定设备、开启通知、查看消息；
8. 浏览器安装到主屏幕；
9. `bash scripts/pre-deploy-test.sh`。
