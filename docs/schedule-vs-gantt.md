# 排程相关页面分工（/schedule vs /gantt vs /multi-schedule）

> 2026-11-05 审计后定稿。三个页面都碰"计划时间/工位"，但职责不同，按下面分工使用。

## 1. 一句话分工

| 页面 | 一句话 | 回答的问题 |
|---|---|---|
| `/schedule` 项目排程 | **跨项目、按周的执行看板** | 本周该干什么？谁干？进度/异常如何？要不要把过期计划整体顺延？ |
| `/gantt` 单项目甘特 | **单项目的计划深度视图** | 这个项目的依赖链对不对？实际干到哪？要不要按约束重算排程？ |
| `/multi-schedule` 资源平衡 | **工位产能与冲突** | 工位够不够？哪个项目抢了哪个工位？要不要改派？ |

## 2. 能力对照

| 维度 | `/schedule` | `/gantt` | `/multi-schedule` |
|---|---|---|---|
| 视角 | 跨项目（可筛项目） | 单项目 | 跨项目（工位维） |
| 主视图 | 本周看板 + 里程碑 + 跨项目甘特 | 单项目甘特（依赖箭头/N 跳/实际进度/告警） | 工位×日热力图 + 冲突表 |
| 改计划时间 | ① 批量平移（RS 批次）② 拖拽改期（DT 批次） | 重新排程（SC 批次，按依赖+工位重算） | 不改时间，只改工位 |
| 依赖维护 | ✅ 抽屉（FS/SS/FF/SF + lag） | 只读箭头 | — |
| 实际进度 | 状态标签 | 计划 vs 实际、项目进度、实际开始标记 | — |
| 告警 | 周看板异常（超期/受阻/未排程） | 本项目告警（工序/里程碑/长运行工单） | 产能超载 + 同工位重叠 |
| 撤销 | 批次抽屉（RS/DT/SC 都可） | 应用后顶部「撤销本次操作」 | — |
| 改工位 | 派工弹窗 | — | 热力图拖拽改派 |

## 3. 三条"改计划时间"路径的差异（重要）

| 路径 | 语义 | 会不会重排依赖 | 保障 |
|---|---|---|---|
| 批量平移 `/schedule` | 整体顺延 N 天 / 对齐锚点，**工期不变** | 不会，只平移选中范围 | 预览 → 应用 → 批次可撤销（`RS-`） |
| 拖拽改期 `/schedule` 甘特 | 手动挪单个工序 | 不会；**会检查直接前后置依赖并告警**（不阻断） | 批次可撤销（`DT-`） |
| 重新排程 `/gantt` | 从项目开始日按依赖+工位**重算全部未完成工序** | 会（跳过已完成节点） | dryRun 预览 → 应用 → 批次可撤销（`SC-`） |

**选择建议**：
- 只是想整体往后挪（甲方延期、等料）→ 批量平移
- 只挪一两个工序、心里有数 → 甘特拖拽（留意依赖告警）
- 依赖或起始日变了、要按约束重算 → `/gantt` 重新排程（先看预览）

## 4. 当前边界与后续

1. 依赖维护抽屉只在 `/schedule`；`/gantt` 只能看箭头。若要两边都能编辑，需把抽屉抽成共享组件（后续）。
2. 派工资质校验只在 `/process_nodes/:id/assign`（process 域），`/schedule` 的派工接口尚未复用（跨服务边界限制，后续需抽公共校验模块）。
3. `/multi-schedule` 改派只改工位不改时间；改派后要回来看是否超载，必要时到 `/schedule` 或 `/gantt` 调日期。
