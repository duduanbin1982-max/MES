# 多项目资源平衡（/multi-schedule）

> 页面：`项目与装备 → 多项目资源平衡`（`/multi-schedule`）  
> 接口：`GET /api/resources/gantt?start_date=&days=&instance_id=&include_completed=`  
> 代码：`frontend/src/views/MultiSchedule.vue`、`frontend/src/domain/workload.ts`、`services/equipment/gantt/resourcesGantt/*`  
> 2026-11-05 按审计整改（详见 `docs/audit-multi-schedule-2026-11-05.md`）。

## 1. 页面能力

| 区域 | 内容 |
|---|---|
| 顶部 | 项目筛选、分析窗口（起始日 + 天数 7~180）、**含历史**开关、刷新 |
| 汇总 | 项目数 / **窗口占用工时**（热力图合计，副指标：任务工时）/ 工位数 / 冲突（超载 + 重叠拆分） |
| Top3 瓶颈 | 峰值利用率最高的三个工位 + 最空闲工位 |
| 热力图 | 工位 × 日，颜色：空闲/正常/繁忙/超载；点击格子看任务并可拖拽改派 |
| 利用率 TOP10 | 平均/峰值利用率、峰值日、已用工时 |
| 项目占用 | 每个项目的节点数、窗口工时、占用工位 |
| 冲突 | 产能超载（工位×日）+ 同工位重叠簇（工位×时间段，带任务数/项目/峰值并发）；可按类型筛选 |

## 2. 口径（重要）

| 指标 | 定义 |
|---|---|
| 窗口占用工时 `window_busy_hours` | 热力图所有格子 `busy_hours` 之和 = 窗口内真实占用 |
| 任务工时 `total_hours` | 窗口内任务 `hours` 之和（长任务会超过窗口占用，仅作参考） |
| 利用率 | `每日忙时 / 每日可用工时`；可用工时 = 班次工时 × 人数，封顶 24h |
| 任务起止 | **计划优先**（`planned_start/planned_end`），无计划才退回实际；只有结束时间时用「结束 − 工时」回推 |
| 历史任务 | 默认排除 `completed/cancelled`；`include_completed=1`（页面「含历史」）可复盘 |
| 冲突聚合 | 同工位重叠按「区间簇」聚合成一条；产能超载按「工位 × 日」一条 |

## 3. 改派规则

| 任务类型 | 接口 | 权限 |
|---|---|---|
| 工序 | `PUT /api/process_nodes/:id/assign` `{required_workstation_id}` | `process:write` |
| 工单 | `PUT /api/work_orders/:id/workstation` `{workstation_id}` | 车间主任 / 管理员 |

- 页面按权限门控：无权限时隐藏拖拽把手、禁用「保存改派」并提示所需权限；
- 保存前二次确认（目标工位 + 条数 + 「改派不改期」提示）；
- 逐条提交并汇总成功/失败，失败给出具体原因（如 403 权限、工位停用）；
- **改派只改工位归属，不改计划时间**；改派后请回到热力图确认目标工位是否超载，必要时用 `/schedule` 或单项目甘特调整日期。

## 4. 2026-11-05 整改要点

1. 默认排除已完成/已取消任务（避免历史占用冒充未来负荷），并提供「含历史」复盘；
2. 工单计划时间修正：取真实 `planned_end`、计划优先、只有结束时间用「结束 − 工时」回推；
3. 冲突聚合：生产 2026-11 窗口 122 条 → 14 条（7 超载 + 7 同工位簇），带峰值并发；
4. 汇总新增 `window_busy_hours`（热力图合计）与 `excluded_completed_count`；
5. 默认窗口改为当前月，并记忆上次窗口/项目/含历史；
6. 项目筛选、含历史开关暴露到页面；
7. 改派权限门控 + 二次确认 + 逐条结果。

## 5. 已知边界（P3）

1. 产能按自然日 7 天计满，未扣周末/节假日（如需工作日历需接排班表）；
2. 冲突行不可点击定位到具体工序/工单（`items` 里带 id，前端暂未做跳转）；
3. 热力图无颜色图例（hover 有文案）、无 CSV 导出；
4. 跨项目冲突只在"同工位"维度识别，没有资源池/外协能力模型。
