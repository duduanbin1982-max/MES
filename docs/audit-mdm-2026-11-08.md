### P0：BOM 检查口径错误，86 条问题全是误报

原规则只检查 `part_number`：

```sql
WHERE part_number IS NULL OR trim(part_number) = ''
```

但生产 BOM 中 86 个节点是 `material_id` 关联物料、没有 `part_number`：

| 情况 | 数量 |
|---|---:|
| 有 material_id、无 part_number | **86** |
| 有 part_number、无 material_id | 69 |
| 两者都无 | **0** |

因此 88 条问题中 86 条是假问题，BOM 域被扣到 0 分，页面几乎不可用。

## 4. 本轮修复

### 4.1 BOM 规则

- 物料锚点改为三选一：
  - `part_number` 非空；
  - `material_id` 非空；
  - `material_code` 非空。
- 新增 `orphan_material_ref`：BOM 引用 `material_id` 但物料主数据不存在。
- 缺字段时明确报 `missing_part_column`，不再静默通过。

### 4.2 人员资质规则

- 优先读取 `worker_certificates`：
  - 有 valid 且未过期证书 → 通过；
  - 无有效证书但有 expired → “证书已过期”；
  - 两者都无且无旧 `cert_no` → “缺少有效证书”。
- 兼容旧 `users.cert_no`，避免历史数据误报。

### 4.3 扫描失败可见

- `_db.js` 的 `all/get` 不再静默吞错，记录 `scan_errors`（去重、最多 30 条）。
- `summary.scan_errors` 随 overview/issues 返回。
- 前端顶部告警：“有 N 条规则扫描失败，结果可能不完整”。

### 4.4 Waiver 闭环

- `POST /mdm/issues/:id/waive`：
  - 问题不存在 → 404；
  - 记录 domain/rule/source/ref_id/reason；
  - 写 `audit_logs`：`mdm.issue.waive`。
- `POST /mdm/issues/:id/reopen`：
  - 未忽略 → 404；
  - 写审计：`mdm.issue.reopen`。
- 新增 `GET /mdm/waivers?active=1`。
- 前端增加“忽略”（原因输入）与“已忽略问题”弹窗（恢复）。

### 4.5 列表/前端

- `/mdm/issues` 返回 `total`、`truncated`；
- 非法 limit 不再返回空；
- 前端展示问题总数与“仅显示前 N 项”；
- overview 支持 `include_issues=0`；
- 加载失败统一 `ElMessage` 提示；
- KPI 更清晰。

## 6. 仍需业务处理

1. **孙焊工补证**：需在人员资质模块补录有效焊工证，否则仍需派工资质校验。
2. **“冒烟导入物料”清理**：两条同名物料，确认是否测试数据或一物多码。
3. **空域评分口径**：当前 0 记录域按 100 分计入平均值，建议改为只统计有记录域。
4. **问题截断**：每条规则 LIMIT 100，大表问题总数可能偏小；建议后续用 COUNT 汇总。
5. **缓存/性能**：overview 与 issues 仍各扫描一次；建议 30~60 秒缓存并在 waiver 变更后失效。
6. **资质角色配置**：worker/welder/qc 硬编码，建议改为岗位主数据配置。
7. **waiver 审计查询**：已写 audit_logs，但 MDM 页面暂未展示操作历史。
