# TBM-MES 分角色速查卡

> 适用系统：`https://192.168.1.73`  
> 用途：把操作手册按岗位拆成一页一张的「速查卡」，打印后贴在工位或电脑旁  
> 用法：每天班前扫一眼「每天固定动作」，班后对一眼「三个数字」；分数不动就看卡点文案  
> 更新日期：2026-10-31  
> 配套：`docs/mes-business-operation-manual.md`（完整手册）、`docs/business-flow-sop.md`（全流程 SOP）、`docs/training-drill-12steps.md`（12 步演练）

## 使用说明

每张卡固定四块：**一句话职责 → 每天固定动作 → 关键页面 → 三个数字与常见错误**。

先记住一句话：**健康检查的分数不动，不是系统坏了，是卡点没人认领。** 打开 `/dashboard` → 「全流程健康检查」，每条「部分/未开始」都会写明具体数字和「去处理」入口。

### 健康检查 8 环节 ↔ 第一责任人

| 环节 | 做到什么算「已通」 | 第一责任人 |
|---|---|---|
| 项目与里程碑 | 有里程碑 且 有合同号 | 项目经理 |
| 设计与 BOM | BOM 行 且 挂物料 且 实装批次覆盖 ≥ 80% | 工艺/工程师 |
| 工艺树与排程 | 工序 且 全部有工位 且 计划时间覆盖 ≥ 80% | 计划员 |
| 派工与报工 | 工单 且 有派工位 且 报工覆盖 ≥ 工单数 | 车间主任 / 操作工 |
| 齐套与领料 | 领料流水 ≥ 1 且 序列号 ≥ 1 | 仓库员 |
| 检验与证据 | 检验 ≥ 1 且（NDT 或 工单检验） | 质检员 |
| 文档与图纸 | 关联到该项目的文档 ≥ 1 | 文控 / 工艺 |
| 交付与成本 | 交付里程碑 且 成本类型 ≥ 2 类 | 项目经理 / 财务 |

## 角色 1｜项目经理（PM）

**一句话职责**：对这个项目的进度、成本、交付负责；用「全流程健康检查」推动卡点闭环。

### 每天固定动作

| 时间 | 做什么 | 在哪 |
|---|---|---|
| 班前 08:30 | 看健康分与 8 环节状态，记下「部分/未开始」 | `/dashboard` 健康检查卡片 |
| 班中 | 处理红色风险（缺料/延误/NCR/ECO） | `/exceptions`、`/delivery` |
| 班后 17:15 | 更新项目进度与关键信息 | `/instances/:id` → 右上角「编辑项目信息」 |
| 每周五 | 30 分钟周会：过健康检查卡点、认领责任人 | `/dashboard?instance_id=` |

### 关键页面

| 场景 | 页面 | 路径 |
|---|---|---|
| 项目体检 + 全局驾驶舱 | 仪表盘 | `/dashboard` |
| 项目交付进度 | 项目交付看板 | `/delivery` |
| 项目详情 / 编辑项目信息 | 项目装备详情 | `/instances/:id` |
| 成本三层差异 + 台账核对 | 项目成本偏差 | `/cost-variance` |
| 经营分析 | 经营分析报表 | `/business-reports` |
| 风险待办 | 异常中心 | `/exceptions` |

### 三个数字与常见错误

每天必看：**健康分（目标 ≥ 85）**、**逾期里程碑数**、**成本偏差合计**。

| 常见错误 | 后果 | 处理 |
|---|---|---|
| 只看分数不看卡点文案 | 分数永远不动 | 逐条读卡点，认领到人 |
| 进度靠记忆不更新 | 驾驶舱与实际不符 | 班后 5 分钟用「编辑项目信息」更新 |
| 成本只看一个总数 | 不知道超在哪 | 看三层差异（量差/价差/效率差）+ 台账核对 |

**点亮环节**：项目与里程碑、交付与成本。

## 角色 2｜计划员

**一句话职责**：把 BOM 和工艺变成可执行的排程与工单，保证工位不打架。

### 每天固定动作

| 时间 | 做什么 | 在哪 |
|---|---|---|
| 班前 | 看待派工单、超载工位（红格） | `/work-orders`、`/multi-schedule` |
| 班中 | 建工单、派工到工位/人、调整排程 | `/work-orders`、`/multi-schedule` |
| 班后 | 确认明日排程，补齐工序计划时间 | `/process-tree`、`/gantt` |
| 每周 | 跑一次多项目资源平衡，处理超载 | `/multi-schedule` |

### 关键页面

| 场景 | 页面 | 路径 |
|---|---|---|
| 工序与依赖 | 工艺树 | `/process-tree` |
| 工单与派工 | 工单管理 | `/work-orders`（`?tab=list` / `?tab=dispatch`） |
| 工位负荷 / 拖拽改派 | 多项目资源平衡 | `/multi-schedule` |
| 关键路径 | 单项目甘特 | `/gantt` |
| 齐套检查 | 齐套缺料 | `/kit-closure` |

### 三个数字与常见错误

每天必看：**待派工单数**、**超载工位数（红格）**、**排程覆盖率**。

| 常见错误 | 后果 | 处理 |
|---|---|---|
| 工序不填工位 | 排不出来 | 工艺树逐条补工位 |
| 工位日能力配置过大 | 热力图偏乐观 | `/workstation-resources` 核对班次 × 人数 |
| 只看甘特不做多项目平衡 | 工位打架 | 用 `/multi-schedule` 看红格 |

**点亮环节**：工艺树与排程、派工与报工（工单 + 派工位部分）。

## 角色 3｜车间主任 / 班组长

**一句话职责**：每天把工单推一格、把报工收全、把异常报上来。

### 每天固定动作

| 时间 | 做什么 | 在哪 |
|---|---|---|
| 班前 08:30 | 看今日任务、未关闭异常 | `/shopfloor`、`/exceptions` |
| 班中 | 派工确认、报工审核、异常上报 | `/work-orders`、`/andon` |
| 班后 17:00 | 推进工单状态、处理异常 | `/work-orders`、`/exceptions` |
| 每周 | 核对工时偏差 | `/process-hours` |

### 关键页面

| 场景 | 页面 | 路径 |
|---|---|---|
| 今日任务 / 扫码报工入口 | 车间工作台 | `/shopfloor` |
| 工单状态与派工 | 工单管理 | `/work-orders` |
| 工时与报工 | 工时与报工 | `/process-hours` |
| 异常与安灯 | 异常中心 / ANDON | `/exceptions`、`/andon` |
| 改派（工序/工单） | 多项目资源平衡 | `/multi-schedule` |

### 三个数字与常见错误

每天必看：**今日任务数**、**报工条数**、**未关闭异常数**。

| 常见错误 | 后果 | 处理 |
|---|---|---|
| 只派工不报工 | OEE 性能/效率差不可信 | 每天收工前检查报工条数 |
| 异常上报后不跟 | 看板长期红灯 | 当天认领、当天回写 |
| 工时随手填 | 成本与效率全歪 | 按实际填写，不凑整 |

**点亮环节**：派工与报工。

## 角色 4｜操作工

**一句话职责**：按图纸和工艺干活；开工、完工、报工；异常立刻上报。

### 每天固定动作

| 时间 | 做什么 | 在哪 |
|---|---|---|
| 开工前 | 扫工序码，看图纸版本、标准工时、注意事项 | `/scan` 或 `/shopfloor?tab=scan` |
| 完工后 | 扫码完工，填实际工时与数量 | 同上 |
| 遇到停料/故障 | 立刻上报，不要自己扛 | `/andon` 或喊班组长 |

### 关键页面

| 场景 | 页面 | 路径 |
|---|---|---|
| 扫码开工 / 完工 / 报工 | 扫码报工 | `/scan` |
| 今日任务与图纸 | 车间工作台 | `/shopfloor?tab=scan` |
| 查图纸 / SOP | 文档/图纸 | `/documents` |

### 三个数字与常见错误

每天必看：**今日工序数**、**已报工时**、**图纸是不是最新版**。

| 常见错误 | 后果 | 处理 |
|---|---|---|
| 忘报工 | 进度和人工成本失真 | 收工前补齐 |
| 拿旧图纸 | 干错返工 | 只看「已签发」的最新版 |
| 遇异常闷着干 | 耽误整条线 | 立即 ANDON |

**点亮环节**：派工与报工（报工工时部分）。

## 角色 5｜质检员

**一句话职责**：来料/过程/出厂检验，焊缝与 NDT，NCR 闭环。

### 每天固定动作

| 时间 | 做什么 | 在哪 |
|---|---|---|
| 班中 | 按工单取检验任务，录检验结果 | `/quality?tab=inspections` |
| 班中 | 焊缝登记、NDT 报告关联焊缝号 | `/tbm-advanced` |
| 班后 | 处理不合格：建 NCR → 处置 → 复检 → 关闭 | `/quality?tab=ncr` |
| 每周 | 看 SPC 控制图，追溯抽查 | `/spc`、`/trace` |

### 关键页面

| 场景 | 页面 | 路径 |
|---|---|---|
| 检验录入 | 质检管理 | `/quality?tab=inspections` |
| NCR / CAPA | 质检管理 | `/quality?tab=ncr` |
| 焊缝 / NDT / 装配记录 | TBM 专项 | `/tbm-advanced` |
| 过程能力 | SPC 控制图 | `/spc` |
| 追溯链 | 端到端追溯 | `/trace` |

### 三个数字与常见错误

每天必看：**待检批次**、**未关闭 NCR**、**缺 NDT 的焊缝**。

| 常见错误 | 后果 | 处理 |
|---|---|---|
| 检验不挂工单 | 合格率统计不到 | 检验时选关联工单 |
| 有焊缝无 NDT | 追溯链缺证据 | 补齐 NDT 并关联焊缝号 |
| NCR 挂着不关 | 质量闭环断 | 按期限关闭 |

**点亮环节**：检验与证据。

## 角色 6｜仓库员

**一句话职责**：批次、库存、领退料、关键件序列号——一切追溯的起点。

### 每天固定动作

| 时间 | 做什么 | 在哪 |

| 按需 | 关键件绑序列号 | `/critical-parts` |

### 关键页面

| 场景 | 页面 | 路径 |
|---|---|---|
| 物料与批次 | 物料中心 | `/materials?tab=materials` |
| 库存清单 | 物料中心 | `/materials?tab=inv` |
| 领料 / 退料 | 车间工作台 | `/shopfloor?tab=pick` |
| 齐套 / 缺料 | 齐套缺料 | `/kit-closure` |
| 库存预警 | 物料预警 | `/material-alerts` |
| 关键件序列号 | 关键件管理 | `/critical-parts` |

### 三个数字与常见错误

每天必看：**缺料项**、**待收批次**、**待登记序列号**。

| 常见错误 | 后果 | 处理 |
|---|---|---|

| 领料不扫码 | 量差算不出来 | 领料必须走出库流水 |
| 关键件不绑序列号 | 只能追到批次 | 关键件逐件登记 |

**点亮环节**：齐套与领料。

**一句话职责**：BOM 结构、图纸签发、ECO、工艺参数——所有工程数据的源头。

### 每天固定动作

| 时间 | 做什么 | 在哪 |
|---|---|---|
| 按需 | BOM 加行 / 改行，挂物料与实装批次 | `/bom` |
| 按需 | 上传图纸/SOP，关联装备（必填）+ BOM 节点 | `/documents` |
| 按需 | ECO 影响评估与执行 | `/eco` |
| 按需 | 工艺树、关键参数维护 | `/process-tree`、`/process-params` |

### 关键页面

| 场景 | 页面 | 路径 |
|---|---|---|
| BOM 结构 / 批次 | BOM 管理 | `/bom` |
| 图纸 / SOP | 文档/图纸 | `/documents` |
| 设计变更 | 设计变更 | `/eco` |

### 三个数字与常见错误

每天必看：**BOM 批次覆盖率**、**待签发/待关联文档**、**未关闭 ECO**。

| 图纸不签发 | 现场用错版 | 签发后现场才能签收 |

**点亮环节**：设计与 BOM、文档与图纸。

## 角色 9｜系统管理员

**一句话职责**：账号权限、数据范围、备份、部署闸门、日常巡检。

### 每天 / 每周固定动作

| 频率 | 做什么 | 在哪 |
|---|---|---|
| 每天 | 看服务健康、备份时长 | `systemctl --user status factory-mes`、`logs/` |
| 每周 | 用户/角色/数据范围复核 | `/users`（`?tab=users/matrix/groups`） |
| 每周 | 审计日志抽查、主数据治理 | `/audit`、`/mdm` |
| 需要时 | 批量导入 / 回滚 | `data-backfill.js`（见 `docs/backfill.md`） |

### 关键页面与命令

| 场景 | 入口 |
|---|---|
| 用户 / 角色 / 角色组 | `/users` |
| 系统设置 | `/settings` |
| 审计日志 | `/audit` |
| 主数据治理 | `/mdm` |
| 工位与资源 | `/workstation-resources` |
| 备份 | `bash scripts/backup-db.sh` |
| 部署闸门 | `bash scripts/pre-deploy-test.sh` |
| 日常巡检 | `bash scripts/ops-daily-check.sh` |
| 数据完备度报告 | `node scripts/data-backfill.js --report` |

### 三个数字与常见错误

每天必看：**最近备份时长（< 6 小时）**、**闸门通过数**、**权限异常账号数**。

| 常见错误 | 后果 | 处理 |
|---|---|---|
| 备份超过 6 小时 | 导入会被拒绝 | 先跑 `backup-db.sh` |
| 权限给太大 | 数据越权 | 用角色组 + 数据范围收紧 |
| 直接改库不备份 | 无法回滚 | 走补录工具 + 边车记录 |

**点亮环节**：全部（通过权限、备份、巡检保障）。
