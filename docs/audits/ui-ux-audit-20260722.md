# TBM-MES 全局 UI/UX 审计报告

> 审计对象：`https://192.168.1.73`  
> 源码位置：`/home/dubin/factory-mes`  
> 审计日期：2026-07-22  
> 审计方法：ui-ux-pro-max 设计基线 + 全量静态扫描 + 64 个菜单入口浏览器验证 + 关键流程多视口截图  
> 审计性质：只读审计；未修改生产代码、数据库和运行配置

## 1. 结论摘要

当前 MES 已具备较完整的业务模块覆盖、菜单分组、设计 token、暗色模式、统一状态组件和工具栏组件，信息架构基础明显好于一般内部管理系统。但部署版本存在一个全局布局根因：内层 `el-container` 未明确纵向排列，导致顶部栏与主内容在桌面端横向分栏，主业务区只剩约 567px；平板和手机端主内容宽度收缩为 0，页面实际不可操作。

同时，浏览器全量验证发现 8 个菜单入口触发 4xx 接口响应，WebSocket 在全部页面握手失败，而左侧仍固定显示“生产在线”。这会直接破坏现场用户对系统状态的信任。

**综合评分：46 / 100，当前不宜作为车间移动端正式版本发布。**

| 维度 | 得分 | 结论 |
|---|---:|---|
| 信息架构与导航 | 74 | 10 个业务分组、搜索、收藏、最近访问较完整 |
| 视觉系统一致性 | 62 | token 基础良好，但登录页、硬编码色、渐变与圆角仍漂移 |
| 桌面布局 | 28 | 全局容器方向错误，主要内容被压缩到右侧窄栏 |
| 响应式与移动端 | 12 | 固定 260px 侧栏占据首屏，主内容宽度为 0 |
| 状态反馈与容错 | 45 | 有 PageState，但覆盖率低，部分 404 被伪装成空数据 |
| 无障碍与可操作性 | 48 | 有 skip link、focus-visible、reduced-motion；仍有非语义点击区和小触控目标 |
| 数据密集型体验 | 51 | 表格丰富，但分页、响应式表格和弹窗适配不足 |
| 实时状态可信度 | 25 | WebSocket 失败、接口 4xx 与静态“生产在线”相互冲突 |

## 4. P0 问题

### P0-1 全局容器方向错误，桌面主内容被压缩

**证据**

- `/home/dubin/factory-mes/frontend/src/views/Layout.vue:18` 的内层 `<el-container>` 未指定 `direction="vertical"`。
- `AppHeader` 是封装组件，Element Plus 容器无法把它识别为直接的 `el-header`，因此内层容器保持默认横向布局。
- 1440px 宽度实测：侧栏 260px、顶部栏 612.8px、主内容 567.2px，三者横向排列。
- 首页、BOM、工艺树、采购、质量、数字孪生截图均显示大面积中间空白，业务内容被挤在最右侧。

**影响**

- 页面栅格、标题和说明文字被压成竖排。
- 表格列、图表、BOM 树和 3D 场景失去可读面积。
- 所有模块共享该问题，属于全局阻断级缺陷。

**修复建议**

1. 内层容器明确设置 `direction="vertical"` 或 `class="app-body"` 并设置 `flex-direction: column; min-width: 0;`。
2. 让 `layout-main` 使用 `flex: 1; min-width: 0; min-height: 0; overflow: auto;`。
3. 增加布局级 Playwright 断言：桌面主内容宽度应等于视口减侧栏宽度，顶部栏与主内容的 `x` 坐标应一致。

### P0-2 平板与手机端主流程不可用

**证据**

- `/home/dubin/factory-mes/frontend/src/components/layout/AppSidebar.vue:2` 固定 `width="260px"`，组件没有移动抽屉或折叠模式。
- `/home/dubin/factory-mes/frontend/src/components/layout/AppHeader.vue:7` 的操作区没有响应式收纳规则。
- 768px 下关键页面横向溢出 103-155px；375px 下溢出 495-548px。
- 两种小屏视口中 `#main-content` 实测宽度均为 0。
- 车间工作台、扫码、领料和质检正是最需要移动端的场景，因此影响高于普通后台页面。

**修复建议**

1. `<=1024px` 将侧栏改为临时抽屉，顶部栏增加菜单按钮。
2. `<=768px` 把操作手册、扫码、时钟、角色标签收进用户菜单或 overflow 菜单。
3. 表格使用横向滚动容器、固定关键列，并为现场任务提供卡片列表视图。
4. 所有弹窗宽度改为 `min(既定宽度, calc(100vw - 24px))`，大抽屉在手机上使用 `100%`。

### P0-3 实时状态与接口状态不可信

**浏览器实测失败**

| 入口 | 请求 | 状态 |
|---|---|---:|
| 仪表盘、OEE | `/api/equipment/oee?days=14/30` | 404 |
| 工艺树 | `/api/equipment_instances/7/process_progress` | 404 |
| SPC | `/api/spc/nodes-with-params` | 404 |
| 采购订单、供应商、采购跟催 | `/api/purchase/orders` | 404 |
| 系统诊断 | `/api/debug/db-stats` | 401（admin） |
| 全部布局页 | `wss://192.168.1.73/ws?...` | 握手失败 |

**源码位置**

- `/home/dubin/factory-mes/frontend/src/api/equipment.ts:33`
- `/home/dubin/factory-mes/frontend/src/composables/useProcessTree.js:64`
- `/home/dubin/factory-mes/frontend/src/views/Spc.vue:110`
- `/home/dubin/factory-mes/frontend/src/views/purchase/usePurchaseOrders.ts:28`
- `/home/dubin/factory-mes/frontend/src/views/settings/SystemDiagnostics.vue:105`
- `/home/dubin/factory-mes/frontend/src/components/layout/AppSidebar.vue:11`

**体验问题**

- OEE 会显示“接口不存在”，采购页面却把 404 显示为“暂无数据”，用户无法判断是没有采购单还是系统故障。
- WebSocket 状态为失败时，侧栏仍用绿色圆点显示“生产在线”，属于状态语义冲突。

**修复建议**

1. 对照服务注册表修复路由装配或前端 API 路径，部署后对 64 入口执行契约冒烟测试。
2. Nginx 明确配置 `/ws` 的 Upgrade/Connection 转发，并验证 101 Switching Protocols。
3. “生产在线”改为真实聚合状态：API、数据库、WebSocket 三者分别显示，禁止静态常绿。
4. 404/401/500 必须进入统一错误态，不得降级为空数据。

## 5. P1 问题

### P1-1 公共状态与工具栏覆盖不足

- 57 个顶层页面中，仅 7 个使用 `PageState`，覆盖率约 12%。
- 仅 6 个页面使用 `PageToolbar`，覆盖率约 11%。
- 253 个 `catch` 代码块中仍有静默降级路径；例如 SPC 404 后直接将节点数组置空。
- 建议先覆盖 64 个菜单入口的页面壳，再逐步覆盖 tab 与抽屉内部状态。

### P1-2 表格扩展性不足

- 73 个页面文件包含 `el-table`，只有审计日志、文档列表、物料流水 3 处包含分页。
- 采购、质量、工单、追溯、成本等高增长数据页面缺少稳定分页或虚拟滚动。
- 建议建立统一 `DataTableShell`：服务端分页、总数、列设置、密度、空值、错误态、导出和移动端列优先级。

### P1-3 弹窗与筛选控件大量使用固定像素

- 存在 350-1100px 固定宽度弹窗，BOM 风险弹窗为 1100px，项目装备向导和权限矩阵为 900px。
- 筛选区大量使用 120-360px 行内宽度，手机端无法自然换行。
- 建议统一使用响应式 dialog token 和 `.toolbar-control--sm/md/lg`，移除页面级行内宽度。

### P1-4 无障碍与触控目标不完整

- 发现 8 个可点击 `div`，包括交付阶段、异常行、工艺卡片、数字孪生图例和 WebSocket 面板触发器；它们缺少按钮语义和键盘行为。
- 侧栏收藏按钮仅 24×24px；移动端应至少 44×44px。
- 图标按钮主要依赖 `title`，只有 1 个文件使用 `el-tooltip`。
- ECharts 配置中未发现 `aria` 配置，也没有数据表替代视图。
- 建议把交互元素改为 button/link，补 `aria-label`、Enter/Space 行为、焦点顺序和图表摘要。

### P1-5 视觉系统存在明显漂移

- `/home/dubin/factory-mes/frontend/src/views/Login.vue:78` 使用高饱和蓝紫渐变，与工业低对比主题完全不同。
- 登录页显示 v2.1，`/home/dubin/factory-mes/frontend/src/components/layout/AppSidebar.vue:8` 显示 v2.3。
- `/home/dubin/factory-mes/frontend/src/views/BomManagement.vue:50` 把 `<el-icon><Share /></el-icon>` 写入 `label` 字符串，浏览器直接显示源码文本。
- 全局卡片圆角 14px、弹窗 16px，页面还有负字距和多处装饰渐变，不符合当前约定的紧凑工业界面。
- 建议登录页复用主主题 token；版本号由构建信息唯一生成；tab 图标使用插槽；圆角收敛到 4/8px 两级。

### P1-6 子模块标题缺少精确上下文

- 多个菜单入口通过 query 参数复用同一路由，例如供应商、采购跟催、来料/过程/出厂检验。
- `/home/dubin/factory-mes/frontend/src/views/Layout.vue:22` 只读取路由 `meta.title`，因此切到子模块后顶部仍显示父页面名称。
- 建议由 module manifest 提供当前 entry 的标题和面包屑，标题应随 `tab/type` 同步变化。

## 6. P2 问题

1. 页面长度仍偏高：操作手册 489 行、项目装备创建向导 475 行、数字孪生 465 行、Gantt 458 行、文档管理 445 行、交付看板 391 行、BOM 386 行。

3. 行内样式集中在追溯、TBM 专项、工时、IoT、扫码、成本、BOM、现场服务等页面，维护和响应式覆盖成本高。

5. 需要建立视觉回归基线，防止未来再次出现“页面能编译但全局布局方向错误”的回归。

## 9. 验收标准

1. 1440/1024/768/375 四档视口下，页面根节点无非预期横向滚动。
2. 桌面端顶部栏与主内容 `x` 坐标一致；手机端主内容宽度等于视口宽度。
3. 64 个菜单入口无 401/404/500，无“Request failed with status code”。
4. WebSocket 返回 101，断线、重连、离线状态在 UI 中准确显示。
5. 采购接口失败时显示错误和重试，不显示“暂无数据”。
6. 所有可点击区域可通过 Tab 到达并用 Enter/Space 操作；移动端触控目标不小于 44px。
7. 所有图表包含标题、legend、ARIA 描述，并提供数据表或导出。
8. 所有固定宽度弹窗在 375px 视口内完整显示，不遮挡关闭和提交按钮。
9. 登录页与主系统使用同一 token、版本号和品牌信息。
10. CI 每次构建执行 64 入口冒烟测试和关键页面截图差异检查。
